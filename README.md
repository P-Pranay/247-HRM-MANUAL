# 247HRM User Manual

A searchable, screen-by-screen user manual for the 247HRM web application, with a **client manual builder** that produces a tailored manual for each client from the modules they purchased and the roles that will use it.

- 90 screens: getting started, settings, all 34 masters, HR operations, employee self-service, dashboards and reports
- 84 screenshots from the 247HRM demo environment
- Instant search across screen names, menu paths, fields, rules and tips (press `/`)
- Client manual builder: upload the purchased-module list (Excel/CSV), pick roles (HR/Admin, Manager, Employee), optionally upload a role's menu list, then download a single self-contained HTML manual for the client

The site is plain HTML, CSS and JavaScript. No framework, no server, no build tools beyond one small Python script.

## Repository layout

```
docs/                 The published site (GitHub Pages serves this folder)
  index.html          Generated by build.py. Do not edit by hand
  img/                Screenshots, one .jpg per screen
src/
  screens.json        All manual content, one object per screen  <- edit this
  meta.json           Module catalogue, prepared date, report count
  template_head.html  Page head and CSS
  app.html            Page JavaScript (navigation, search, builder, export)
build.py              Assembles docs/index.html from src/
tools/                Scripts originally used to turn the demo-site capture into screens.json (reference only)
```

## Publish on GitHub Pages

1. Create a repository (private is recommended, see the note below) and push this folder.
2. In the repository go to **Settings > Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**, branch `main`, folder `/docs`, then **Save**.
4. After a minute the site is live at `https://<org>.github.io/<repo>/`.

Private repositories need a paid GitHub plan for Pages, and GitHub Enterprise Cloud to restrict who can view the published site.

## Edit content

1. Change `src/screens.json`. Each screen looks like this:

```json
{
  "id": "hr-payroll",
  "group": "HR operations",
  "title": "Payroll",
  "icon": "calculate",
  "path": "☰ Menu > HR > Payroll",
  "summary": "One or two sentences on what the screen is for.",
  "next": "The first thing to do on the screen.",
  "can": ["What the user can do", "..."],
  "concepts": [["Term", "Explanation"]],
  "rules": ["Validation rules"],
  "tips": ["Shortcuts"],
  "watch": ["Common mistakes"],
  "fields": [{"step": "Basic Information", "sub": "", "fields": [{"label": "Name", "req": true, "hint": ""}]}],
  "tabs": ["Tab names on the screen"],
  "extra": [["Box title", "Box text", "optional module key"]],
  "img": "r-payroll",
  "mod": "payroll",
  "roles": ["hr"]
}
```

   - `icon` is any [Material Symbols](https://fonts.google.com/icons) name.
   - `img` is the file name in `docs/img/` without `.jpg`. Leave it empty for no screenshot.
   - `mod` is the module key from `src/meta.json` (`core`, `payroll`, `itax`, `attendance`, `leave`, `letters`, `helpdesk`, `travel`, `asset`, `timesheet`, `ats`, `pms`, `rewards`) or `base` for screens every client gets.
   - `roles` lists who sees the screen: `hr`, `manager`, `employee`.
   - Screens appear in the order they are listed. Screens with the same `group` are grouped in the side menu.

2. Run `python3 build.py`. It checks for missing fields, duplicate ids, unknown modules and missing images.
3. Commit `src/` and `docs/` together and push.

To add a screenshot, save it as `docs/img/<name>.jpg` (about 800 px wide works well) and set `"img": "<name>"` on the screen.

To add or rename a sellable module, edit the `modules` list in `src/meta.json`. Each entry is `[key, display name, short description, upload aliases separated by |]`. The aliases are how an uploaded module list is matched, so add the names clients and the sales team actually use.

## Before publishing publicly

The screenshots come from the 247HRM demo company. Check them before making the site public:

- `docs/img/r-profile.jpg` shows a demo user's name, designation and email address. The builder hides it from client copies by default, but the file is still in the repository.
- Several list screenshots show demo employee names and salary totals.

Replace or blur these, or keep the repository and its Pages site private.

## Local preview

Open `docs/index.html` in a browser, or run `python3 -m http.server --directory docs 8000` and visit http://localhost:8000. Use the HTTP server when testing the builder's download: browsers block reading the screenshots from `file://`, so a client manual downloaded from a file:// page has no images.
